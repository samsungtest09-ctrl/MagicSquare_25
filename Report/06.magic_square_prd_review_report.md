# Magic Square PRD 검토 보고서

## 1. 목적
- 직전에 작성된 PRD 문서를 기준으로 누락, 모순, 모호함을 점검한다.
- 점검 기준은 아래 7가지 항목으로 고정한다.
  1) 모든 FR에 테스트 가능한 AC 존재 여부  
  2) 모든 AC의 Traceability Matrix 연결 여부  
  3) Boundary/Domain 책임 혼합 여부  
  4) 오류 정책 미정 항목 존재 여부  
  5) small-first 성공 vs reverse 성공 테스트 데이터 분리 여부  
  6) 1-index 좌표 및 row-major 규칙 반영 여부  
  7) 구현/테스트 코드 포함 여부

## 2. 종합 판단
- 전반적으로 PRD 구조와 내용은 구현 전 기준 문서로 사용 가능한 수준이다.
- 다만 **Traceability 누락 1건**, **오류 정책 체계 불일치**, **레이어 책임 표기 모호성**이 확인되어 보완이 필요하다.

## 3. 점검 결과 요약

| 점검 기준 | 결과 | 비고 |
|---|---|---|
| FR별 테스트 가능한 AC 존재 | 충족 | FR-01~FR-05 모두 AC 명시 |
| AC와 Traceability 연결 | 부분 미충족 | FR-02-AC-02 누락 |
| Boundary/Domain 책임 분리 | 부분 미충족 | FR-05 및 일부 컴포넌트 표기 혼합 |
| 오류 정책 확정성 | 부분 미충족 | ERR-DESIGN 코드 미정의, 실패 노출 방식 미정 |
| small-first/reverse 데이터 분리 | 충족 | TD-001, TD-002 분리 |
| 1-index/row-major 규칙 반영 | 충족 | BR/FR/Traceability 모두 반영 |
| 구현/테스트 코드 포함 금지 | 충족 | 코드 블록 없음 |

## 4. 상세 이슈

### 4.1 Traceability 누락
- 이슈: `FR-02-AC-02`가 Traceability Matrix에 명시적으로 연결되지 않음.
- 영향: AC 완전 추적성 저하.
- 개선 권고: Matrix에 FR-02-AC-02 전용 행 추가.

### 4.2 오류 코드 체계 불일치
- 이슈: `ERR-DESIGN-001~005`가 Contract 섹션에 존재하나 Error Policy 표에는 정의되지 않음.
- 영향: 구현/테스트 시 코드 기준 혼선 가능.
- 개선 권고:  
  - 옵션 A: `ERR-DESIGN-*`를 정책 표에 정식 등록  
  - 옵션 B: `ERR-BND-*`, `ERR-DOM-*`만 유지하도록 단일화

### 4.3 실패 정책 외부 노출 방식 미확정
- 이슈: `ERR-DOM-001` 자체는 정의되었으나 외부 전달 방식(직접 예외/래핑 응답)이 미정.
- 영향: Boundary 계약과 런타임 실패 응답 형식 불일치 위험.
- 개선 권고: 노출 정책을 하나로 확정하고 Open Question 해소.

### 4.4 레이어 책임 표기 모호성
- 이슈: FR-05 레이어가 `Control + Domain + Boundary(Output)`로 집계 표기됨.
- 영향: 책임 경계가 해석 의존적으로 변할 수 있음.
- 개선 권고: 오케스트레이션/판정/포맷 역할을 계층별로 명확 분리 표기.

## 5. 결론
- 본 PRD는 핵심 구조(계약, 불변식, Dual-Track, Traceability)를 갖추고 있으며, 즉시 개선이 필요한 항목은 제한적이다.
- 우선순위는 다음과 같다.
  1) AC-Traceability 완전 연결  
  2) 오류 코드 체계 단일화  
  3) 실패 응답 노출 정책 확정  
  4) FR-05 계층 책임 명확화
