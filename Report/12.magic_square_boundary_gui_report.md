## 1. 목적

- 사용자가 4×4 마방진 퍼즐을 **그래픽 인터페이스**로 입력·실행할 수 있도록 boundary 레이어에 GUI 어댑터를 추가한다.
- ECB 의존 방향을 유지하며, GUI는 `boundary.facade.validate_and_solve`만 호출하고 entity/control을 직접 참조하지 않는다.
- 실행 진입점과 테스트를 함께 제공하여 Track A(Boundary/UI) 확장 기반을 마련한다.

## 3. 아키텍처

### 3.1 ECB 의존 방향

```
[Tkinter GUI — boundary/gui]
        │
        ▼
[boundary.facade.validate_and_solve]
        │
        ├── BoundaryValidator.validate (형상/null)
        └── Solver.resolve (미구현)
```

| 허용 | 금지 |
|---|---|
| `boundary/gui` → `boundary.facade` | `boundary/gui` → `entity` 직접 |
| `boundary/gui` → `boundary.models` (DTO 표시) | GUI 내부 Domain 검증 로직 |
| `logging` 사용 | 운영 코드 `print()` |

### 3.2 입력 계약

| 항목 | 규칙 |
|---|---|
| 빈칸 표현 | 빈 문자열 또는 `0` → `BLANK_CELL_VALUE` (0) |
| 허용 범위 | 0, 1~16 (`MIN_CELL_VALUE`~`MAX_CELL_VALUE`) |
| 파싱 오류 | `GridInputParseError` — 1-index 좌표 포함 메시지 |
| 격자 형상 | 반드시 4×4 (`GRID_SIZE`) |

### 3.3 런타임 동작

| 입력 상태 | facade 동작 | GUI 표시 |
|---|---|---|
| 셀 파싱 실패 | facade 미호출 | `오류: 셀 (r,c): ...` |
| 형상/null 위반 | `ValidationFailureResult` 반환 | `[INVALID_SIZE] Grid must be 4x4.` |
| 유효 4×4 격자 | `NotImplementedError` (현재) | `입력 형식은 올바릅니다. 풀이 기능은 아직 구현 중입니다.` |
| 풀이 성공 (향후) | `list[int]` 길이 6 | 빈칸 좌표·숫자 1-index 표시 |
