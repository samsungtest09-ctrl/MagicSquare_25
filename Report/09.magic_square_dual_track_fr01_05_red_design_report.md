## 2. 프로젝트 계약 요약

| 항목 | 규칙 |
|---|---|
| **입력** | 4×4 `int[][]`; `0`=빈칸(정확히 2개); 값 `0` 또는 `1~16`; non-zero 중복 금지 |
| **출력** | `int[6]` = `[r1,c1,n1,r2,c2,n2]`; 좌표 **1-index** |
| **마방진 상수** | 4×4 → M=34 (`MagicConstant` SSOT) |
| **검증 순서 (short-circuit)** | null → size → empty count → value range → duplicate |
| **Boundary invalid** | Failure envelope 반환 (Python 예외 아님) |
| **오류 코드** | E003 null, E001 size, E002 empty count, E004 range, E005 duplicate |
| **invalid 시** | `SolvePartialMagicSquare.execute` **0회** (U-FLOW-02) |
| **PRD 매핑** | E003↔ERR-BND-001, E001↔002, E002↔003, E004↔004, E005↔005 |

### 2.1 Failure envelope (Boundary)

```text
FailureEnvelope { code: str, message: str }
```

- RED Then은 **code·message exact**만 고정한다.
- 필드명·DTO 타입은 GREEN 단계에서 확정한다.

## 4. Logic Invariant SSOT (I1~I11)

| ID | 내용 |
|---|---|
| **I1** | 4개 행 각각 합 = M(34) |
| **I2** | 4개 열 각각 합 = M |
| **I3** | 주대각선·반대각선 합 = M |
| **I4** | 값 ∈ {1..16}, `0` 없음, 중복 없음 |
| **I5** | I1~I4 종합 판정 (`is_magic_square`) |
| **I6** | row-major 첫·둘째 빈칸 좌표 1-index |
| **I7** | 누락 숫자 2개, 오름차순 |
| **I8** | Attempt1 small-first 성공 → `[r1,c1,small,r2,c2,large]` |
| **I9** | Attempt2 reverse 성공 → `[r1,c1,large,r2,c2,small]` |
| **I10** | 양 Attempt 실패 → `UnsolvableDomainError` / ERR-DOM-001 |
| **I11** | 누락 집합 완전성: `{1..16} \ present`, \|missing\| = 2 |

## 9. ECB·Dual-Track 정합

```
[Caller] → Boundary (U-IN, U-OUT, U-FLOW)
              ↓ (valid only)
           Control (D-SOL)
              ↓
           Entity (D-LOC, D-MIS, D-VAL)
```

- 허용: `boundary → control → entity`
- 금지: `boundary → entity` 직접, Domain Mock(Logic Track), invalid 시 execute 호출
