## STEP 1 — 관찰 (Observation)

### 1. 현재 우리가 해결하려는 상황은 무엇인가?

16개의 서로 다른 자연수를 4×4 격자에 배치했을 때, **모든 행·열·대각선의 합이 동일한 값을 가져야 한다는 조건**이 존재한다. 이 조건은 단순히 숫자를 채우는 행위가 아니라, 숫자 간의 **구조적 관계**를 만족시키는 배치를 찾는 상황이다.

### 2. 왜 4×4 마방진 문제를 다루는가?

- 1×1, 2×2는 자명하거나 불가능하고, 3×3은 해가 본질적으로 하나(회전·반사 제외)다.
- 4×4는 **해가 다수 존재**하면서도 조건의 복잡도가 관리 가능한 수준이다.
- "단 하나의 정답을 외우는" 문제가 아니라 **조건을 만족하는 공간을 탐색하는** 문제로서 의미가 있다.

### 3. 어떤 학습 또는 시스템 설계 맥락에서 등장하는가?

| 맥락 | 설명 |
|---|---|
| **규칙 기반 시스템 설계** | 불변 조건(invariant)을 명시하고, 그 조건을 코드로 표현하는 훈련 |
| **TDD 학습** | 구현 이전에 "무엇이 참인가"를 먼저 정의하는 사고 방식 훈련 |

## STEP 2 — Why #1

### Q. 왜 마방진을 완성해야 하는가?

**A (가정):** 사용자가 16개의 숫자를 직접 격자에 채웠을 때, 자신의 배치가 올바른지 즉시 알 수 없다.

#### 이 답에서 드러나는 불편함과 구조적 문제

- **검증 불가능성** — 사람이 직접 모든 행·열·대각선의 합을 손으로 계산해야 한다. 실수가 발생해도 발견하기 어렵다.
- **피드백 부재** — 어디가 틀렸는지, 어떤 조건을 위반했는지에 대한 즉각적인 정보가 없다.
- **반복 불가능성** — 새로운 배치를 시도할 때마다 처음부터 다시 검증해야 한다.
- **조건의 암묵성** — "합이 같아야 한다"는 조건이 명시적으로 정의되지 않은 채로 작업이 진행된다.

> **구조적 문제:** 조건이 암묵적이고, 검증이 수동적이며, 피드백 루프가 존재하지 않는다.

## STEP 3 — Why #2

### Q. 왜 단순 계산이 아니라 프로그램으로 구현하는가?

| 관점 | 설명 |
|---|---|
| **반복 가능성** | 동일한 조건을 오차 없이 반복 적용할 수 있다 |
| **검증 자동화** | 조건 자체를 코드로 표현함으로써 검증 행위가 자동화된다 |
| **오류 방지** | 조건 위반 시 즉시, 일관되게 알려준다. 오류 발견이 오류 발생 직후로 앞당겨진다 |
| **규칙 기반 사고 훈련** | 모호한 직관을 정밀한 조건으로 번역하는 사고 능력을 훈련한다 |

## STEP 4 — Why #3 (핵심 발견)

### Q. 왜 이 문제를 TDD 방식으로 설계하려 하는가?

#### 무엇이 통제되어야 하는가?

- 배치된 숫자의 **유효성** (중복 없음, 범위 준수)
- 각 행·열·대각선의 **합의 동일성**
- 입력으로 주어지는 배치가 **완전한가** (모든 칸이 채워져 있는가)

#### 핵심 Invariant

| 불변 조건 | 설명 |
|---|---|
| **합의 불변성** | 1~16을 사용할 때 모든 행·열·대각선의 합은 반드시 34 |
| **유일성 불변성** | 각 숫자는 격자 전체에서 정확히 한 번만 등장해야 함 |
| **완전성 불변성** | 16개의 칸이 모두 채워져야 마방진으로 판정 가능 |

#### 왜 입력/출력이 명확해야 하는가?

TDD에서 테스트는 **"어떤 입력에 대해 어떤 출력이 나와야 하는가"** 를 먼저 선언한다. 입력과 출력이 모호하면 테스트 자체를 작성할 수 없다. 마방진 문제는 조건이 수학적으로 명확하기 때문에 입력/출력을 정밀하게 정의하는 훈련에 이상적이다.

## STEP 5 — 진짜 문제 정의

### 1. 표면 문제 정의 (잘못된 정의)

> "1부터 16까지의 숫자를 4×4 격자에 넣어서 마방진을 만드는 프로그램을 작성한다."

이 정의는 출력 형태에만 집중하고, 조건의 구조·검증 방법·설계 목적을 전혀 포함하지 않는다.

### 2. 개선된 문제 정의 (정확한 정의)

> "4×4 격자에 배치된 16개의 숫자가 **행·열·두 대각선의 합이 모두 동일하다는 불변 조건**을 만족하는지를 **자동으로 검증할 수 있는 시스템**을 설계한다. 이 시스템은 조건 위반 시 어떤 조건이 어떻게 위반되었는지를 명확히 식별할 수 있어야 한다."

### 3. 이 문제의 핵심 Invariant

```
모든 유효한 4×4 마방진 M에 대해 다음이 참이다:

  ① M의 모든 원소는 서로 다르며 정해진 집합 내의 값이다.
  ② 임의의 행 i에 대해: sum(M[i][*]) = S  (상수)
  ③ 임의의 열 j에 대해: sum(M[*][j]) = S
  ④ 주대각선의 합 = S
  ⑤ 반대각선의 합 = S
  ⑥ S는 배치된 숫자 집합에 의해 결정되며, 임의로 선택되지 않는다.
```

> 조건 ①이 선행되지 않으면 ②~⑥은 의미가 없다. 조건의 **순서와 의존 관계** 자체가 설계의 핵심이다.

### 4. 우리가 실제로 훈련하려는 사고 능력

| 사고 능력 | 설명 |
|---|---|
| **조건의 명문화** | 직관적으로 "맞다"고 느끼는 것을 반박 불가능한 조건으로 언어화하는 능력 |
| **의존 관계 파악** | 어떤 조건이 다른 조건의 전제인지, 순서를 틀리면 무엇이 무너지는지를 인식하는 능력 |
| **불변 조건 설계** | 시스템이 어떤 상태에서도 반드시 지켜야 할 것을 식별하는 능력 |
| **입력/출력 경계 정의** | 시스템의 책임 범위를 명확히 선언하는 능력 |
| **검증 우선 사고** | "어떻게 만드는가" 이전에 "어떻게 참임을 증명하는가"를 먼저 묻는 사고 습관 |

## 목적 확정 — 퍼즐 모드

### 확정된 목적

> **사용자가 4×4 격자의 칸을 직접 채우고, 프로그램은 그 배치가 마방진의 조건을 만족하는지를 검증하여 피드백을 제공한다.**

### 시스템 역할 비교

| 관점 | 자동 생성 모드 (제외) | 퍼즐 모드 (채택) |
|---|---|---|
| **입력** | 없음 | 사용자가 채운 16개의 숫자 |
| **주체** | 프로그램 | 사람 |
| **핵심 행위** | 조건을 만족하는 배치를 스스로 구성 | 사용자의 배치가 조건을 만족하는지 판정 |
| **출력** | 완성된 배치 | 합격/불합격 + 어떤 조건이 위반되었는가 |
| **피드백 방향** | 없음 | 사용자에게 돌아감 |

### 시스템 입력/출력 경계

```
입력:  사용자가 직접 채운 4×4 배치 (16개의 숫자)
           │
           ▼
     [ 검증 시스템 ]
           │
           ▼
출력:  ① 전체 합격 / 불합격 판정
       ② 불합격 시 — 어떤 행/열/대각선이 조건을 위반했는가
       ③ 불합격 시 — 중복 또는 범위 위반이 있는가
```

## 요구사항 명세 (Requirements Specification)

### 용어 정의 (Glossary)

| 용어 | 정의 |
|---|---|
| **배치(Arrangement)** | 사용자가 4×4 격자에 입력한 16개 숫자의 집합 |
| **기준값 S** | 마방진이 성립할 때 모든 행·열·대각선이 가져야 하는 공통 합. 1~16 사용 시 S = 34 |
| **검증(Validation)** | 배치가 마방진 조건을 만족하는지 판정하는 행위 |
| **판정(Verdict)** | 검증의 최종 결과 — PASS 또는 FAIL |
| **위반(Violation)** | 특정 조건을 만족하지 못하는 상태 |
| **피드백(Feedback)** | 위반 발생 시 사용자에게 전달되는 구체적 정보 |

---

### 기능 요구사항 (Functional Requirements)

#### FR-01. 입력 수용
- 시스템은 사용자로부터 4×4 크기의 숫자 배치를 입력받아야 한다.
- 입력의 형식(한 번에 16개 / 행 단위 / 칸 단위)은 인터페이스 설계 단계에서 결정한다.

#### FR-02. 검증 실행
- 시스템은 입력된 배치에 대해 아래 명세 순서대로 검증을 수행해야 한다.
- 각 검증 단계는 독립적으로 식별 가능해야 한다.

#### FR-03. 판정 출력
- 시스템은 검증 결과로 **PASS** 또는 **FAIL** 을 반환해야 한다.
- PASS는 모든 조건을 만족한 경우에만 반환된다.

#### FR-04. 위반 피드백
- FAIL인 경우, 어떤 조건이 위반되었는지를 구체적으로 알려야 한다.
- 피드백은 **어디서, 무엇이, 얼마나** 틀렸는지를 포함해야 한다.

---

### 검증 명세 상세 (Validation Specification)

#### VS-01. 완전성 검사 (Completeness)

| 항목 | 내용 |
|---|---|
| **조건** | 16개의 칸이 모두 채워져 있어야 한다 |
| **위반 기준** | 비어 있는 칸이 1개 이상 존재하는 경우 |
| **위반 시 동작** | 검증을 중단하고 피드백 반환 |
| **피드백 내용** | 비어 있는 칸의 위치 (행, 열) |
| **다음 단계 진행 여부** | 실패 시 VS-02 이후 진행 불가 |

#### VS-02. 유일성 검사 (Uniqueness)

| 항목 | 내용 |
|---|---|
| **조건** | 16개의 값에 중복이 없어야 한다 |
| **위반 기준** | 동일한 값이 2개 이상 존재하는 경우 |
| **위반 시 동작** | 검증을 중단하고 피드백 반환 |
| **피드백 내용** | 중복된 값, 해당 값이 위치한 칸들의 좌표 |
| **다음 단계 진행 여부** | 실패 시 VS-03 이후 진행 불가 |

#### VS-03. 범위 검사 (Range)

| 항목 | 내용 |
|---|---|
| **조건** | 모든 값이 허용 범위 내에 있어야 한다 (기본: 1 이상 16 이하) |
| **위반 기준** | 범위를 벗어난 값이 1개 이상 존재하는 경우 |
| **위반 시 동작** | 검증을 중단하고 피드백 반환 |
| **피드백 내용** | 범위를 벗어난 값과 그 위치 |
| **다음 단계 진행 여부** | 실패 시 VS-04 이후 진행 불가 |

#### VS-04. 행 합 검사 (Row Sum)

| 항목 | 내용 |
|---|---|
| **조건** | 4개의 행 각각의 합이 S(=34)와 같아야 한다 |
| **위반 기준** | 합이 S가 아닌 행이 1개 이상 존재하는 경우 |
| **위반 시 동작** | 해당 행을 기록하고 VS-05로 계속 진행 |
| **피드백 내용** | 위반된 행 번호, 실제 합, 기대값 S |
| **다음 단계 진행 여부** | 실패해도 VS-05 이후 계속 검사 |

#### VS-05. 열 합 검사 (Column Sum)

| 항목 | 내용 |
|---|---|
| **조건** | 4개의 열 각각의 합이 S와 같아야 한다 |
| **위반 기준** | 합이 S가 아닌 열이 1개 이상 존재하는 경우 |
| **위반 시 동작** | 해당 열을 기록하고 VS-06으로 계속 진행 |
| **피드백 내용** | 위반된 열 번호, 실제 합, 기대값 S |
| **다음 단계 진행 여부** | 실패해도 VS-06 이후 계속 검사 |

#### VS-06. 대각선 합 검사 (Diagonal Sum)

| 항목 | 내용 |
|---|---|
| **조건** | 주대각선과 반대각선의 합이 각각 S와 같아야 한다 |
| **위반 기준** | 두 대각선 중 하나라도 합이 S가 아닌 경우 |
| **위반 시 동작** | 해당 대각선을 기록 |
| **피드백 내용** | 위반된 대각선 방향, 실제 합, 기대값 S |

### 검증 흐름 요약

```
사용자 입력
    │
    ▼
VS-01 완전성 ── FAIL ──► 검증 중단 + 피드백 (위치)
    │ PASS
    ▼
VS-02 유일성 ── FAIL ──► 검증 중단 + 피드백 (중복값, 위치)
    │ PASS
    ▼
VS-03 범위   ── FAIL ──► 검증 중단 + 피드백 (범위 초과값, 위치)
    │ PASS
    ▼
VS-04 행 합  ── 위반 기록 (계속 진행)
    │
    ▼
VS-05 열 합  ── 위반 기록 (계속 진행)
    │
    ▼
VS-06 대각선 ── 위반 기록
    │
    ▼
위반 없음 → PASS
위반 있음 → FAIL + 전체 위반 목록 피드백
```

> VS-01~03은 **선행 조건**이므로 실패 시 즉시 중단한다.
> VS-04~06은 **독립 조건**이므로 실패해도 모두 검사한 뒤 통합 피드백을 제공한다.

### 경계 조건 및 예외 상황 (Edge Cases)

| 상황 | 분류 | 처리 방향 |
|---|---|---|
| 0이 입력된 경우 | 범위 위반 | VS-03에서 탐지 |
| 음수가 입력된 경우 | 범위 위반 | VS-03에서 탐지 |
| 17 이상의 값이 입력된 경우 | 범위 위반 | VS-03에서 탐지 |
| 같은 값이 두 칸 이상에 존재하는 경우 | 유일성 위반 | VS-02에서 탐지 |
| 행 합은 맞지만 열 합이 틀린 경우 | 열 조건 위반 | VS-05에서 탐지 |
| 모든 합이 맞지만 대각선만 틀린 경우 | 대각선 조건 위반 | VS-06에서 탐지 |
| 완벽한 마방진이 입력된 경우 | PASS | 모든 검사 통과 |

### 비기능 요구사항 (Non-Functional Requirements)

| 항목 | 요구사항 |
|---|---|
| **피드백 명확성** | 위반 메시지는 행/열 번호와 실제 합·기대값을 포함해야 한다 |

| **확장성** | 숫자 범위나 격자 크기 변경 시 검증 구조가 크게 바뀌지 않아야 한다 |
