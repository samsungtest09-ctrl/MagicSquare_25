# 4×4 마방진 — 문제 인식 단계

## STEP 1 — Observation (관찰)

### 1. 현재 우리가 해결하려는 상황은 무엇인가?

16개의 서로 다른 자연수를 4×4 격자에 배치했을 때, 모든 행·열·대각선의 합이 동일한 값을 가져야 한다는 조건이 존재한다. 이 조건은 단순히 숫자를 채우는 행위가 아니라, 숫자 간의 구조적 관계를 만족시키는 배치를 찾는 상황이다.

### 2. 왜 4x4 마방진 문제를 다루는가?

- 1×1, 2×2는 자명하거나 불가능하고, 3×3은 해가 본질적으로 하나(회전·반사 제외)다.
- 4×4는 해가 다수 존재하면서도 조건의 복잡도가 관리 가능한 수준이다.
- "단 하나의 정답을 외우는" 문제가 아니라 조건을 만족하는 공간을 탐색하는 문제로서 의미가 있다.

### 3. 어떤 학습 또는 시스템 설계 맥락에서 등장하는가?

| 맥락 | 설명 |
|---|---|
| 규칙 기반 시스템 설계 | 불변 조건(invariant)을 명시하고, 그 조건을 코드로 표현하는 훈련 |
| TDD 학습 | 구현 이전에 "무엇이 참인가"를 먼저 정의하는 사고 방식 훈련 |

---

## STEP 2 — Why #1

**A (가정):** 사용자가 16개의 숫자를 직접 격자에 채웠을 때, 자신의 배치가 올바른지 즉시 알 수 없다.

드러나는 구조적 문제:
- **검증 불가능성** — 손으로 계산해야 하며 실수가 발생해도 발견하기 어렵다.
- **피드백 부재** — 어디가 틀렸는지, 어떤 조건을 위반했는지에 대한 즉각적인 정보가 없다.
- **반복 불가능성** — 새로운 배치를 시도할 때마다 처음부터 다시 검증해야 한다.
- **조건의 암묵성** — "합이 같아야 한다"는 조건이 명시적으로 정의되지 않은 채로 작업이 진행된다.

---

## STEP 3 — Why #2

| 관점 | 설명 |
|---|---|
| 반복 가능성 | 동일한 조건을 오차 없이 반복 적용할 수 있다 |
| 검증 자동화 | 조건 자체를 코드로 표현함으로써 검증 행위가 자동화된다 |
| 오류 방지 | 조건 위반 시 즉시, 일관되게 알려준다 |
| 규칙 기반 사고 훈련 | 모호한 직관을 정밀한 조건으로 번역하는 사고 능력을 훈련한다 |

## STEP 4 — Why #3 (핵심 발견)

**통제되어야 하는 것:**
- 배치된 숫자의 유효성 (중복 없음, 범위 준수)
- 각 행·열·대각선의 합의 동일성
- 입력으로 주어지는 배치가 완전한가 (모든 칸이 채워져 있는가)

**불변 조건:**

| 불변 조건 | 설명 |
|---|---|
| 합의 불변성 | 1~16을 사용할 때 모든 행·열·대각선의 합은 반드시 34 |
| 유일성 불변성 | 각 숫자는 격자 전체에서 정확히 한 번만 등장해야 함 |
| 완전성 불변성 | 16개의 칸이 모두 채워져야 마방진으로 판정 가능 |

## STEP 5 — 진짜 문제 정의

**표면 문제 정의 (잘못된 정의):**
> "1부터 16까지의 숫자를 4×4 격자에 넣어서 마방진을 만드는 프로그램을 작성한다."

**개선된 문제 정의 (정확한 정의):**
> "4×4 격자에 배치된 16개의 숫자가 행·열·두 대각선의 합이 모두 동일하다는 불변 조건을 만족하는지를 자동으로 검증할 수 있는 시스템을 설계한다."

**핵심 Invariant:**
```
① M의 모든 원소는 서로 다르며 정해진 집합 내의 값이다.
② 임의의 행 i에 대해: sum(M[i][*]) = S
③ 임의의 열 j에 대해: sum(M[*][j]) = S
④ 주대각선의 합 = S
⑤ 반대각선의 합 = S
⑥ S는 배치된 숫자 집합에 의해 결정되며, 임의로 선택되지 않는다.
```

**훈련하려는 사고 능력:**

| 사고 능력 | 설명 |
|---|---|
| 조건의 명문화 | 직관을 반박 불가능한 조건으로 언어화하는 능력 |
| 의존 관계 파악 | 조건 간 순서와 전제 관계를 인식하는 능력 |
| 불변 조건 설계 | 시스템이 항상 지켜야 할 것을 식별하는 능력 |
| 입력/출력 경계 정의 | 시스템의 책임 범위를 명확히 선언하는 능력 |
| 검증 우선 사고 | "어떻게 만드는가" 이전에 "어떻게 참임을 증명하는가"를 먼저 묻는 사고 습관 |

**시스템 입력/출력 경계:**
```
입력:  사용자가 직접 채운 4×4 배치 (16개의 숫자)

     [ 검증 시스템 ]
           │
           ▼
출력:  ① 전체 합격 / 불합격 판정
       ② 불합격 시 — 어떤 행/열/대각선이 조건을 위반했는가
       ③ 불합격 시 — 중복 또는 범위 위반이 있는가
```

**TDD 검증 명세 (추상 수준):**

- 검증 명세 1 — 완전성: 16개의 칸이 모두 채워져 있어야 검증을 시작할 수 있다.
- 검증 명세 2 — 유일성: 입력된 16개의 값에 중복이 없어야 한다.
- 검증 명세 3 — 범위: 모든 값이 허용된 범위 내에 있어야 한다.
- 검증 명세 4 — 행 합의 동일성: 4개의 행 각각의 합이 기준값 S와 같아야 한다.
- 검증 명세 5 — 열 합의 동일성: 4개의 열 각각의 합이 S와 같아야 한다.
- 검증 명세 6 — 대각선 합의 동일성: 주대각선과 반대각선의 합이 S와 같아야 한다.

# 요구사항 명세 (Requirements Specification)

## 용어 정의 (Glossary)

| 용어 | 정의 |
|---|---|
| 배치(Arrangement) | 사용자가 4×4 격자에 입력한 16개 숫자의 집합 |
| 기준값 S | 마방진이 성립할 때 모든 행·열·대각선이 가져야 하는 공통 합. 1~16 사용 시 S = 34 |
| 검증(Validation) | 배치가 마방진 조건을 만족하는지 판정하는 행위 |
| 판정(Verdict) | 검증의 최종 결과 — PASS 또는 FAIL |
| 위반(Violation) | 특정 조건을 만족하지 못하는 상태 |
| 피드백(Feedback) | 위반 발생 시 사용자에게 전달되는 구체적 정보 |

## 기능 요구사항

- **FR-01. 입력 수용:** 사용자로부터 4×4 크기의 숫자 배치를 입력받아야 한다.
- **FR-02. 검증 실행:** 입력된 배치에 대해 명세 순서대로 검증을 수행해야 한다.
- **FR-03. 판정 출력:** 검증 결과로 PASS 또는 FAIL을 반환해야 한다.
- **FR-04. 위반 피드백:** FAIL인 경우, 어디서·무엇이·얼마나 틀렸는지를 알려야 한다.

## 검증 명세 상세

| ID | 검사명 | 조건 | 위반 시 동작 | 이후 진행 |
|---|---|---|---|---|
| VS-01 | 완전성 | 16개 칸 모두 채워짐 | 중단 + 빈 칸 위치 피드백 | 중단 |
| VS-02 | 유일성 | 중복 값 없음 | 중단 + 중복값·위치 피드백 | 중단 |
| VS-03 | 범위 | 1 이상 16 이하 | 중단 + 초과값·위치 피드백 | 중단 |
| VS-04 | 행 합 | 각 행의 합 = 34 | 위반 기록 후 계속 | 계속 |
| VS-05 | 열 합 | 각 열의 합 = 34 | 위반 기록 후 계속 | 계속 |
| VS-06 | 대각선 합 | 양 대각선의 합 = 34 | 위반 기록 후 계속 | 계속 |

## 검증 흐름

```
VS-01 완전성 ── FAIL ──► 중단
    │ PASS
VS-02 유일성 ── FAIL ──► 중단
    │ PASS
VS-03 범위   ── FAIL ──► 중단
    │ PASS
VS-04 행 합  ── 기록 → VS-05 열 합 ── 기록 → VS-06 대각선 ── 기록
    │
위반 없음 → PASS  /  위반 있음 → FAIL + 통합 피드백
```
